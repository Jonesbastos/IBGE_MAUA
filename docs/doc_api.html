API de Localidades do IBGE: Mauá (SP)

Especificação técnica detalhada, dicionário de campos, contratos de dados e scripts de ingestão/transformação para o município de Mauá (Código IBGE 3529401).

1. Objetivo & Finalidade da API

A API de Localidades do IBGE (Serviço de Dados do Instituto Brasileiro de Geografia e Estatística) provê o repositório cadastral canônico e padronizado da organização territorial e político-administrativa do Brasil.

Para a nossa arquitetura de Engenharia de Dados, esta API atua como a tabela dimensão territorial central (Lookup Table / Master Data), viabilizando:

  • Garantia de integridade com a chave primária oficial nacional (Código de 7 dígitos do IBGE);
  • Rastreabilidade das divisões regionais históricas (Mesorregiões/Microrregiões de 1989);
  • Conformidade com a nova divisão político-econômica contemporânea (Regiões Intermediárias/Imediatas de 2017);
  • Agrupamento padronizado por Unidade da Federação e Macrorregião geográfica.

2. Especificação dos Endpoints HTTP

Endpoint 1: Listagem de Municípios por Estado (São Paulo)

Retorna todos os 645 municípios paulistas. Ideal para cargas em lote (batch ingestion) do estado de SP.

URL: https://servicodados.ibge.gov.br/api/v1/localidades/estados/35/municipios

Método: GET  |  Retorno: application/json; charset=utf-8  |  Cache: max-age=2592000 (~30 dias)

Endpoint 2: Consulta Direta por Município (Mauá)

Recuperação pontual com baixa latência utilizando a chave primária de Mauá (3529401).

URL: https://servicodados.ibge.gov.br/api/v1/localidades/municipios/3529401

Método: GET  |  Retorno: application/json; charset=utf-8  |  Autenticação: Nenhuma (Pública)

⚠️ Alerta de Arquitetura: Hífens nas Chaves
As chaves regiao-imediata e regiao-intermediaria possuem hífens. No pipeline de dados, elas devem ser normalizadas para regiao_imediata e regiao_intermediaria antes de carregar em Data Warehouses ou modelos tabulares para evitar erros de sintaxe SQL.

7. Exemplo de Consumo com Python e Requests

Implementação orientada a produção com sessão HTTP resiliente, retries e timeout configurado:

import requests
from requests.adapters import HTTPAdapter
from urllib3.util import Retry
from typing import Optional, Dict, Any

MAUA_URL = "https://servicodados.ibge.gov.br/api/v1/localidades/municipios/3529401"

def get_ibge_session() -> requests.Session:
    """Instancia sessão resiliente com pool de conexões e retries."""
    session = requests.Session()
    retry_policy = Retry(
        total=3,
        backoff_factor=0.5,
        status_forcelist=[429, 500, 502, 503, 504],
        raise_on_status=False
    )
    adapter = HTTPAdapter(max_retries=retry_policy)
    session.mount("https://", adapter)
    return session

def extrair_dados_maua() -> Optional[Dict[str, Any]]:
    session = get_ibge_session()
    headers = {"Accept": "application/json"}
    try:
        response = session.get(MAUA_URL, headers=headers, timeout=(3.05, 10.0))
        response.raise_for_status()
        return response.json()
    except requests.exceptions.RequestException as e:
        print(f"[Erro na Ingestão] Falha ao coletar dados: {e}")
        return None
    finally:
        session.close()

if __name__ == "__main__":
    payload = extrair_dados_maua()
    if payload:
        print(f"Extração concluída: {payload['nome']} (ID: {payload['id']})")

8. Normalização e Achatamento em Pandas

Transformação do JSON aninhado em modelo tabular de 1 linha utilizando pd.json_normalize:

import pandas as pd

def criar_dataframe_maua(raw_json: dict) -> pd.DataFrame:
    # 1. Normalização do JSON com separador '_'
    df = pd.json_normalize(raw_json, sep="_")

    # 2. Saneamento de colunas (removendo hífens gerados por 'regiao-imediata')
    df.columns = df.columns.str.replace("-", "_", regex=False).str.lower()

    # 3. Forçar dtypes explícitos
    types = {
        "id": "int64",
        "nome": "string",
        "microrregiao_id": "int64",
        "microrregiao_nome": "string",
        "microrregiao_mesorregiao_uf_sigla": "string"
    }
    for col, dt in types.items():
        if col in df.columns:
            df[col] = df[col].astype(dt)

    return df

9. Validações e Regras de Data Quality

Regras Mandatórias de Validação

  • Regra 1: Integridade do Código IBGE (7 Dígitos): Deve ser inteiro positivo de exatamente 7 dígitos, iniciando com 35 (SP) e dígito verificador válido.
  • Regra 2: Null Checks: Campos id, nome, UF.sigla e regiao.nome não toleram valores nulos.
  • Regra 3: Preservação de Acentos UTF-8: O campo nome deve ser estritamente "Mauá", rejeitando sequências corrompidas de encoding.
  • Regra 4: Detecção de Schema Drift: Alterações de contrato pelo IBGE acionam falha antecipada (Fast-Fail) na camada Bronze.

10. Limitações Críticas da API de Localidades

⚠️ Restrição Importante de Escopo de Dados
A API de Localidades do IBGE NÃO fornece diretamente indicadores socioeconômicos ou estatísticos, tais como:
  • População residente ou censitária;
  • Produto Interno Bruto (PIB) municipal ou PIB per capita;
  • Índice de Desenvolvimento Humano (IDHM) ou renda média;
  • Estatísticas de saúde, emprego, saneamento ou educação.

Como enriquecer estes dados no projeto:
Para incorporar esses indicadores analíticos nas fases subsequentes da pipeline, utilizaremos a API SIDRA do IBGE (Sistema IBGE de Recuperação Automática) e a API de Agregados / Pesquisas: 

# Endpoint canônico da API SIDRA/Agregados para indicadores de Mauá (N6[3529401]):
https://servicodados.ibge.gov.br/api/v3/agregados/{agregado}/periodos/{ano}/variaveis/{variavel}?localidades=N6[3529401]
